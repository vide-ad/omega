# @omega/web — Omega Training PWA

Installable, offline-capable training log for iPhone Safari (spec §7). Vite 7 + React 19 +
TypeScript, `vite-plugin-pwa` (Workbox `generateSW`, auto-update), Dexie for IndexedDB. No UI or
router libraries — a hash router (`src/router.ts`) and plain CSS (`src/styles.css`).

## Run

```sh
# from the repo root (deps are installed with pnpm 10 / Node 22)
pnpm --filter @omega/web dev        # http://localhost:5173, proxies /api → http://localhost:8787
pnpm --filter @omega/web test       # vitest (pure outbox / timer / session / router / format logic + render smoke tests)
pnpm --filter @omega/web typecheck  # tsc --noEmit (strict, noUncheckedIndexedAccess)
pnpm --filter @omega/web build      # typecheck + vite build → dist/ (index.html, sw.js, manifest.webmanifest, icons/)
pnpm --filter @omega/web preview    # serve dist/ locally
```

`@omega/core` is consumed from its built `dist` — run `pnpm build:core` at the root if the engine changed.

## Pointing it at the API

All HTTP goes through `src/api/client.ts`, which reads `{ baseUrl, token }` from `localStorage`
(keys `omega.baseUrl`, `omega.token`). Open **Settings** (⚙):

- **Base URL** — leave blank when the PWA is served by `@omega/api` on the same origin (the
  default). Set e.g. `https://omega.example.com` when the app is hosted elsewhere (the API must then
  allow CORS for that origin).
- **Token** — the `OMEGA_TOKEN_WRITE` value (logging is a write). A read token works for browsing
  but every mutation is rejected with 403 and surfaces in the sync badge.
- **Test connection** — `GET /api/health` then `GET /api/v1/mesocycles/current` and reports what failed.

In dev the Vite server proxies `/api` to `http://localhost:8787`, so a blank base URL works there too.

## Install on iPhone

1. Open the app URL in **Safari** (not an in-app browser). HTTPS or `localhost` is required for the
   service worker; a plain-http LAN address will run but not install/offline-cache.
2. Tap **Share** → **Add to Home Screen** → **Add**.
3. Launch **Omega** from the home screen. It runs standalone (no Safari chrome, portrait, dark),
   keeps the screen awake during a session, and works offline.

Rest-timer sound needs one tap anywhere first (iOS audio unlock); vibration is used where the
browser supports it (not iOS Safari).

## Screens (hash routes)

| Route | Screen |
|---|---|
| `#/` | Today, current mesocycle/week/deload, start-template buttons, resume in-progress session, readiness card, week volume strip |
| `#/session/:id` | **Active session** — per exercise: targets, suggested weight + rationale, flags, constraint notes, previous numbers, set rows (weight, reps, one-tap RIR chips 0–5 with −/+, pain none→niggle→moderate→stop + note, warm-up, AMRAP), add/remove set; rest timer bar; notes, session RPE, finish + summary |
| `#/workout/:id` | Read-only session detail (same view) |
| `#/readiness` | Morning form: bodyweight, RHR, sleep, quality/stress/motivation chips, rough-day toggle, soreness for recently trained muscles |
| `#/volume` | Per-muscle bars vs targets for the selected week (`GET /volume?weeks=4`) |
| `#/history` | Workout list → detail |
| `#/settings` | API base URL/token, test connection, sync status/queue, iOS install steps, clear local data |

## Offline model

See `docs/API.md` "Offline model".

- `src/offline/db.ts` — Dexie tables `cache {key, value, updated_at}` and
  `outbox {op_id, method, path, body, created_at, attempts, last_error}`.
- `src/offline/outbox.ts` — pure functions over an injected store interface: `enqueue` (queue +
  optimistic apply to every cached entity the op touches), `replay` (in `created_at` order; stops
  on the first failure — network/5xx are retried later, a 4xx is kept and surfaced as *rejected*
  so it never loops), `applyPending` (re-apply queued ops over a fresh server response).
  Unit-tested with in-memory stores (no fake-indexeddb needed).
- `src/offline/sync.ts` — browser wiring: single-flight replay on `online`,
  `visibilitychange → visible`, and after every enqueue while online; sync status events.
- `src/offline/cache.ts` — network-first reads with cache fallback; the top bar shows an
  **offline** pill when a screen is served from cache.
- Every create carries a client UUID, so replay is idempotent (`POST` with an existing id → 200).
- Starting a session (`POST /workouts`) needs a connection because the server runs the progression
  engine; everything after that (sets, edits, deletes, notes, finish, readiness) queues offline.

Workbox: the app shell is precached; `GET /api/v1/*` uses `NetworkFirst` with a 4 s timeout
(cache `omega-api-v1`); `POST/PATCH/DELETE` are never cached.
